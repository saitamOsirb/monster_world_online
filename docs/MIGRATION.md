# Godot → PixiJS migration

## Baseline

Behavioral/reference source: `arkeve/Godot-Pokemon` at commit `f0527ebbf3717398d4a980b63993ad4e04c9580d`.

The target runtime does **not** embed Godot, GDScript, `AnimationTree`, `TileMap`, `RayCast2D`, `CanvasLayer` or Godot scene execution. Legacy `.tscn/.tres` files are treated as import data only.

## Runtime architecture

```text
src/
  game/
    Game.ts                    application loop, camera, transitions
    constants.ts               preserved 240x160 / 16px gameplay contracts
    entities/Player.ts         player state machine and animation slicing
    input/InputController.ts   keyboard edge/held state
    ui/MenuController.ts       menu + party state
    world/
      CollisionWorld.ts        deterministic grid queries
      LegacyGodotImporter.ts   TSCN/TileMap data decoder
      TileMapRenderer.ts       Pixi tile rendering
      WorldScene.ts            scene assembly and object/resource reuse
```

`public/assets` and `public/legacy` are generated by `pnpm assets:sync` and intentionally excluded from Git. This keeps the TypeScript source repository clean while still allowing local reuse of the upstream resources.

| 16×16 grid | Migrated | Used by movement, camera and collision. |

## Intentional cleanups

- Gameplay state is explicit TypeScript instead of being spread across scene nodes and animation callbacks.
- Movement and collision are deterministic grid operations; rendering does not decide whether movement is legal.
- Input edge state is centralized rather than handled independently by several scene scripts.
- Scene transitions do not destroy/recreate the player object.
- Assets are synchronized as resources; `.import` files and Godot-generated metadata are not carried forward.

## Remaining parity work

1. Import `CollisionShape2D` rectangles generically, including transforms from instantiated scenes. The current slice handles water and gameplay layers directly and uses conservative footprints for trees/buildings.
2. Convert Godot `AnimatedTexture` water frames to a Pixi animation rather than using the first water frame.
3. Recreate door open/close animation timing before the scene transition.
4. Recreate all grass-step and landing-dust animation frames rather than the current lightweight effect.
5. Rebuild the party screen from the original UI textures/font for pixel-identical visuals.
6. Import interior collision geometry for `OaksLab.tscn`, `PlayerHomeFloor1.tscn` and `RivalHomeFloor.tscn`.
7. Add visual regression fixtures for Pallet Town and the interiors after collision import is complete.

## Scope note

The upstream repository is an overworld/interaction prototype. It does not contain a complete Pokémon battle engine, encounter system, capture system, move database or RPG progression implementation. Those systems should be designed as new modules rather than presented as migrated functionality.

## Resource and licensing note

The upstream GitHub repository reports no repository license. Its Pokémon names/artwork/resources also relate to third-party intellectual property. The sync script is provided to reproduce the requested technical migration from the referenced project, but the repository should not assume that upstream assets are cleared for redistribution or commercial use. For an original game, replace those resources with assets you have rights to use before distribution.
